# 会话自动归档与清理

后台 Host 插件，不调用模型。启动 3 秒后检查，此后每小时检查一次；应用关闭时不运行，重启后补查。

- 按创建时间与全部日志事件时间的最大值计算最后活动时间，严格超过 5×24 小时归档。
- 已归档且最后活动严格超过 14×24 小时，永久删除本地会话日志全部格式版本；不是归档后再等 14 天。
- 新归档的会话本轮不删除，至少保留至下一轮。
- 跳过所有已加载会话（即使闲置）和置顶会话；归档不强行终止任务。
- 有子会话的父会话不删除，子会话先清理后下轮再处理父会话，避免破坏历史依赖。
- 删除只支持当前 JSONL 存储：持有官方写句柄的跨进程排他锁，重新检查时间和归档状态，仅删除经校验的日志文件，不递归删除目录。锁文件和空目录保留。
- 不删除项目文件、共享附件或远端副本。外部读取者已持有的历史快照可能在刷新前仍可见。
- 当前 DSH 无删除 API，日志删除为后端维护适配；未知目录文件、符号链接、硬链接、缺少归档状态等均拒绝清理并记录错误。升级 DSH 后应重新验证。
- 运行摘要保存在当前 profile 的 `session-retention/latest.json`，只记录 ID 和错误，不记录对话正文。

配置：`archiveAfterDays: 5`、`deleteAfterDays: 14`、`intervalMinutes: 60`。`reportDirectory` 可显式指定摘要目录，不影响清理范围；默认目录取自宿主当前 profile。可在插件管理中禁用；禁用不会恢复已删除日志。

从旧版迁移时，先记下阈值、报告目录和启用状态，停用旧条目；在启用新条目 `dsh-session-retention` 前重新应用并核对这些设置，避免两个清理任务同时运行。
